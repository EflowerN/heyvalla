# HeyValla collaboration rule

Do not push any changes to a remote unless the user explicitly asks for that push. An earlier push request does not authorize pushing later work. Keep new changes local until requested.

## Public data provenance

For public data sources outside the organizer-provided list in `docs/data-sources.md`, save a reference in that register. The user exempts the organizer-provided sources and datasets supplied through that list from additional project reference entries; do not require duplicate references for those sources. Preserve any attribution required by the actual dataset license, including existing map attribution. For other public sources, Record the publisher, source URL and dataset/feed URL where available, retrieval date, source version/update date when known, what data was used and where it is stored, transformations, licensing/attribution information, and limitations. Preserve source metadata with imported data and retain required attribution in the UI. Distinguish verified source data from fictional demo assumptions. Do not treat public availability as proof of unrestricted reuse or operational accuracy. Update the register when adding or refreshing data.

## Product colours

Follow `docs/design-system.md` for the user-approved app palette and transport identity colours: flight light blue, sea dark blue, land orange, taxi black and bus green. Keep mode identity distinct from selection/status styling, and accompany colour with text labels.

## Judging priorities

The user supplied weighted datathon judging criteria. Consult `docs/feature-audit-and-judging-plan.md` when prioritizing features and preparing the demo. Technical execution (20%), impact (15%) and scalability/readiness (15%) together carry half the marks. Keep real, historical, provider-entered and simulated data distinguishable.
